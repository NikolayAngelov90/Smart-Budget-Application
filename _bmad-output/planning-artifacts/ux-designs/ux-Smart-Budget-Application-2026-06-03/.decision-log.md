# Decision Log — Mobile UX Overhaul (Smart Budget)

Run: ux-Smart-Budget-Application-2026-06-03 · Mode: Create (Fast path) · Facilitator capture

## Scope

Focused mobile-UX redesign of the existing Smart Budget PWA (brownfield, Next.js 15 + Chakra UI). Not a full-app rebrand — the Trust Blue identity and existing screens stay. This UX defines the **mobile shell**: safe-area handling, viewport, and a single contemporary navigation model.

## Context captured (from inspection + user direction, 2026-06-03)

1. **Problem 1 — Dynamic Island overlap.** Root cause: `apple-mobile-web-app-status-bar-style: black-translucent` + `viewport-fit=cover` make content draw under the status bar, but `Header.tsx` (sticky, top:0) has no `env(safe-area-inset-top)` padding. Title + hamburger are obscured on iPhone 14/15/16.
2. **Problem 2 — `100vh`.** `AppLayout` uses `h="100vh"`; mobile browser chrome makes this cut off content / jump. Fix: `100dvh`.
3. **Problem 3 — redundant navigation.** Two parallel mobile navs exist: a hamburger drawer (`MobileNav.tsx`: Dashboard, Transactions, Categories, Insights, Settings) and a bottom tab bar (`BottomNav.tsx`: Dashboard, Transactions, +Add, Insights, Settings). Confusing; "Categories" only lives in the drawer.
4. **Problem 4 — account menu reach.** User/account actions are a top-right Chakra dropdown — worst thumb-reach corner on a phone.

## Research grounding (2026-06-03)

- iOS PWA safe area: with `black-translucent`, fixed header + bottom nav must pad with `env(safe-area-inset-*)`. (danielpietzsch.com; itnext.io)
- Bottom tab bar is the modern standard for 3–5 primary destinations (Apple HIG, Material). Hamburger reduces feature discovery 30–50%, adds a tap, and the top-left is poor for one-handed reach. Redbooth: +65% DAU / +70% session after hamburger→tabs. (appmysite.com; onething.design; nngroup.com)

## Decisions

- **D1 — UI system:** Chakra UI remains the system. Both spines inherit Chakra defaults; specify deltas only.
- **D2 — Visual identity unchanged:** Trust Blue (#2b6cb0) primary, existing scale (`src/theme/colors.ts`). No new palette.
- **D3 — Safe areas:** Header pads top with `env(safe-area-inset-top)`; BottomNav keeps `env(safe-area-inset-bottom)` and adds left/right insets. Blue header fills the Dynamic Island region; content sits below it.
- **D4 — Viewport:** root shell uses `100dvh` (dynamic viewport), `overscroll-behavior-y: none` on the scroll container.
- **D5 — Single primary nav on mobile:** the **bottom tab bar is the only primary nav**. Retire the hamburger drawer as a primary navigator.
- **D6 — Categories placement:** move "Categories" off the hamburger. Mobile tabs stay 4 + center Add (Dashboard, Transactions, +Add, Insights, Settings). Categories is reached from within Transactions/Settings (secondary). [ASSUMPTION] — confirm whether Categories deserves a primary tab; default is secondary.
- **D7 — Account actions:** replace the top-right dropdown with an **account bottom-sheet** (Chakra Drawer placement="bottom") opened from the header avatar — reachable, native-feeling. Holds email, account/settings link, sign-out.
- **D8 — Tab bar polish:** translucent blurred background (`backdrop-filter`), active-tab color + label weight, ≥48×48 targets (keep), elevated center Add (keep).
- **D9 — Accessibility:** restore pinch-zoom (drop `maximumScale: 1`) unless it breaks the map/chart gestures. [ASSUMPTION] — confirm.
- **D10 — Desktop/tablet untouched:** sidebar + FAB remain ≥ md breakpoint. This is a `base`-breakpoint (mobile) change.

## Open questions — RESOLVED (2026-06-03, user)

- OQ1 (D6): **Categories = secondary** (reached from Transactions/Settings; not a bottom tab). Bottom bar stays 4 + Add.
- OQ2 (D9): **Restore pinch-zoom** (drop `maximumScale: 1`) for accessibility.
- OQ3: **Remove the hamburger entirely** on mobile. Bottom tabs are the sole primary nav; account moves to the avatar bottom-sheet. `MobileNav.tsx` retired on mobile.
