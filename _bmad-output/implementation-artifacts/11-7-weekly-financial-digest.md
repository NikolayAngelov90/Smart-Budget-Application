# Story 11.7: Weekly Financial Digest

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a user who wants passive financial awareness,
I want to receive a weekly digest summarizing my spending, trends, and highlights,
So that I stay informed without actively checking the app daily.

## Acceptance Criteria

1. **Given** a user has opted into the weekly digest (default: enabled), **When** the weekly digest cron runs (Monday 08:00 UTC), **Then** a digest is generated for each eligible user containing: total spending for the previous week, comparison to the week before (% change), top 3 spending categories, and one actionable highlight.

2. **Given** a digest has been generated for a user, **When** the user views their dashboard, **Then** the `WeeklyDigestCard` is visible on the dashboard showing the week's spending summary, change indicator (up/down), top categories, and actionable highlight.

3. **Given** a user has never had a digest generated (new user, first week), **When** they view the dashboard, **Then** no `WeeklyDigestCard` is rendered — progressive disclosure applies.

4. **Given** the digest cron runs, **When** a digest for the same `(user_id, week_start)` already exists, **Then** the cron does NOT generate a duplicate — upsert or idempotent skip.

5. **Given** a user has `weekly_digest_enabled: false` in their preferences, **When** the cron runs, **Then** no digest is generated for that user, and no digest card appears on their dashboard.

6. **Given** a digest is rendered, **When** spending increased vs. the previous week, **Then** the change percentage is shown in red with an up-arrow. **When** spending decreased, it is shown in green with a down-arrow.

7. **Given** a digest is rendered, **When** a screen reader user navigates to it, **Then** all digest information is accessible — spending totals, category names, and the actionable highlight are announced correctly.

> **Out of Scope for this story:** Push notification delivery (deferred to Story 15.5 — push infrastructure per ADR-018 does not exist yet). The AC "digest can be delivered as a push notification if enabled" will be wired in Story 15.5 when `push_subscriptions` table and service worker are implemented.

- [ ] Task 3: `digestService.ts` — core computation logic (AC: #1, #4, #5)
  - [ ] 3.1 Create `src/lib/services/digestService.ts`:
    - `generateDigestForUser(userId: string, weekStart: Date): Promise<void>`
      - Compute `weekEnd = endOfWeek(weekStart, { weekStartsOn: 1 })`
      - Compute `prevWeekStart = subWeeks(weekStart, 1)`, `prevWeekEnd = subWeeks(weekEnd, 1)`
      - Query transactions for both weeks (join with categories for name/color):
        ```sql
        SELECT t.amount, t.category_id, c.name, c.color
        FROM transactions t JOIN categories c ON t.category_id = c.id
        WHERE t.user_id = userId AND t.type = 'expense'
          AND t.date >= weekStart AND t.date <= weekEnd
        ```
      - Sum totals; group by category_id; sort desc; take top 3
      - Do same for previous week for `previous_week_spending`
      - Compute `spending_change_pct`: `(total - prev) / prev * 100` (if prev=0, use 0)
      - Generate `actionable_highlight` via rule-based text (see below)
      - Upsert: `supabase.from('weekly_digests').upsert({ user_id, week_start, ... }, { onConflict: 'user_id,week_start' })`
      - Use `createServiceRoleClient()` (not user-scoped client — cron bypasses RLS)
    - `getLatestDigest(supabase: SupabaseClient, userId: string): Promise<WeeklyDigest | null>`
      - `SELECT * FROM weekly_digests WHERE user_id = userId ORDER BY week_start DESC LIMIT 1`
      - Return null if not found (PGRST116 silent)

    **Actionable highlight rules** (simple rule-based, no AI):
    ```typescript
    function buildHighlight(total: number, prevTotal: number, topCats: DigestTopCategory[], currency: string): string {
      const pct = prevTotal > 0 ? ((total - prevTotal) / prevTotal) * 100 : 0;
      if (pct > 15) return `Your spending increased by ${Math.round(pct)}% — check your ${topCats[0]?.name ?? 'top'} category.`;
      if (pct < -15) return `Great job! Spending dropped ${Math.round(Math.abs(pct))}% vs last week.`;
      if (topCats[0] && topCats[0].total / total > 0.5) return `${topCats[0].name} made up over 50% of your spending this week.`;
      return `You spent ${formatAmount(total, currency)} this week across ${topCats.length} categories.`;
    }
    ```

### What Already Exists (Do NOT Re-Implement)

- **Cron auth pattern**: `src/app/api/cron/subscription-detect/route.ts` — COPY THIS PATTERN exactly:
  - `timingSafeEqual(Buffer.from(token), Buffer.from(cronSecret))` for constant-time comparison
  - `createServiceRoleClient()` from `@/lib/supabase/server`
  - Batch size 20 with `Promise.all(batchPromises)`
  - Return `{ success, usersProcessed, ..., errors, elapsedMs }`

- **SWR hook pattern**: `src/lib/hooks/useSubscriptions.ts` — COPY pattern for `useWeeklyDigest`

- **`date-fns` is already installed at v4.1.0**. Used in `subscriptionService.ts`. Import from `'date-fns'`:
  ```typescript
  import { startOfWeek, endOfWeek, subWeeks, format, parseISO } from 'date-fns';
  ```
  In date-fns v4, `startOfWeek` accepts `{ weekStartsOn: 1 }` option (1 = Monday). No breaking changes for these functions from v3→v4.

- **`createServiceRoleClient()`** is in `@/lib/supabase/server` (not `createClient()`). It bypasses RLS. Only use in cron routes and `digestService.generateDigestForUser`.

- **`logger`** from `@/lib/utils/logger` — use same logging pattern as subscription-detect: `logger.info('WeeklyDigestCron', message)`, `logger.error(...)`.

- **Dashboard placement**: Add `WeeklyDigestCard` below `AnnualizedProjections` in `src/app/dashboard/page.tsx`. The component self-manages progressive disclosure — renders null when no data. Dashboard does NOT need conditional logic.

- **`user_preferences` is JSONB**: The `preferences` column in `user_profiles` is a JSONB field. To check if digest is disabled:
  ```typescript
  const digestEnabled = user.preferences?.weekly_digest_enabled !== false; // default true
  ```
  Note: `preferences` comes as `Json` (unknown) — use `(user.preferences as Record<string, unknown>)?.weekly_digest_enabled !== false`.

### Architecture Compliance

1. **Service function accepts Supabase client for `getLatestDigest`** — consistent with goalService, subscriptionService pattern. `generateDigestForUser` creates its own service-role client internally (cron context only).

2. **No `!` non-null assertions** in source files — use `?.` optional chaining.

3. **Consistent API error shape** — `{ error: { message: '...' } }` with status code.

4. **`export const dynamic = 'force-dynamic'; export const revalidate = 0;`** on `GET /api/user/digest`.

5. **`spending_change_pct` when previous week = 0**: return `0` (not `Infinity`). If `prevTotal === 0 && total > 0`, use `100` as a sensible bounded value.

6. **DECIMAL precision**: Store amounts with 2 decimal places. Do not use `toFixed()` as a DB value — pass as `Number` (Supabase handles serialization).

7. **`date-fns` week boundary**: The cron runs Monday 08:00 UTC. `subWeeks(new Date(), 1)` gives a date in the previous week. `startOfWeek(thatDate, { weekStartsOn: 1 })` gives the Monday of last week. Verify this in tests with fixed dates.

8. **Upsert idempotency**: `supabase.from('weekly_digests').upsert(payload, { onConflict: 'user_id,week_start' })` — prevents duplicate digests if cron runs twice.

9. **Zod v4 compatibility** (if using Zod in cron route for body validation — not needed here since cron has no body). If validating response, use `error:` not `invalid_type_error:`.
