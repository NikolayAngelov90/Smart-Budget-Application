## 2. What went well

**Measuring instead of guessing** *(Nikit's pick)*

- Production-build audits with in-browser contrast, overflow and tap-target
  measurement replaced eyeballing.
- It **closed an item carried for three epics**: household mobile legibility
  had been waiting on a screenshot since Epic 13. Story 16-7 measured it and
  found it does not reproduce. Waiting would never have closed it.
- It **prevented two wrong fixes**. Twice a test fixture encoded a data
  combination that does not exist in production — a stored `exchange_rate`
  with no `currency` (0 of 217 rows), and the `trends` range ending at month
  end rather than today. Querying production first meant correcting the
  fixture instead of weakening the code to match it.

**Deciding before building** *(Nikit's pick)*

- Explicit decision points preceded implementation: period-selector semantics
  (16-6), the six DW-5 product questions, and the DW-4 delivery model.
- DW-4 is the clearest case. Choosing the model first surfaced that a
  sent-marker with a **daily** cron can never recover a deferral — the retry
  lands at the same hour and the user is still asleep. Discovering that
  mid-implementation would have meant building the wrong mechanism first.

**Adversarial review caught what self-review did not**

Found in review, not by the author: the hero printing "THIS MONTH" twice; last
month's figures rendered under "THIS YEAR" during a period switch; a 4.01:1
admin badge in dark mode; and a false claim that a guard had been proven
non-vacuous.

**Design-system guards now encode the lessons**

`designSystemGuards.test.ts` catches the *dynamic* `colorScheme` form and
badge-pill-vs-card contrast — the two blind spots that let this drift happen.

## 3. What did not go well

**Our verification method was wrong for most of the epic.**

Stories 16-1 → 16-5 verified colour migration by grepping for `"blue"`. It
passed every time and was wrong every time: `colorScheme={x ? 'blue' : 'gray'}`
does not match a value-grep, so seven dynamic expressions kept painting
Chakra's `#3182ce` through five stories. 16-7 found them only by rendering the
pages and reading computed colours from the DOM.

The same shape appeared a second time: the contrast audit measures **text on
background**, so a badge whose *pill* is invisible against its card passes with
readable text. `achievement.surface` on a white card is **1.01:1**. The first
version of the new guard had the identical blind spot.

> **A check that cannot fail for the reason you care about is not a check.**

**Severity was assigned from fix difficulty, not user impact.**

Four items in `deferred-work.md` were filed LOW or MED-latent and were in fact
wrong-numbers or data-integrity bugs:

| Filed as | Actually |
|---|---|
| `[LOW, pre-existing Epic 5]` | Dashboard windows included an extra day for anyone east of UTC |
| `[MED-latent]` | Reconnect revalidation (AC-8.5.4) had **never once fired** |
| `[LOW]` | Shared-category delete could partially orphan other members' transactions |
| `[LOW]` | Quiet hours evaluated in UTC — "22:00" meant 01:00 for a UTC+3 user |

**The partial-mock trap, three times in one epic.**

`@/lib/utils/date`, `InsightMetadata`, and `notification_deliveries`. Each time
a module gained an export (or a route gained a table) and an explicit
`jest.mock` factory silently returned `undefined`. This is Epic 15 action item
#3 (itself carried from Epic 14) — the debt now has a measured cost.

**Three process failures by the implementer, recorded deliberately.**

1. **A completeness claim that was false.** "No global-mutate callers remain" —
   grepped only `import { mutate }`, missed six files using
   `mutate as globalMutate`. Corrected in the following PR.
2. **A circular non-vacuity proof.** Claimed a guard was proven by injecting a
   regression, but changed the component *and* the test's expected value in the
   same step, so the failure came from the test edit. Two reviewers caught it
   independently. **Change one side, not both.**
3. **A verification probe left junk data in a production row.** All CTEs in one
   statement share a snapshot, so the cleanup step did not apply. Caught,
   removed and verified — but the operator should have been tested on literals,
   which touches nothing.

**Concurrent reviewers mutate the working tree.**

Review agents injected regressions to test findings and restored from their own
backups, clobbering in-flight edits twice. Every intended change had to be
re-verified against git before committing.

## 5. Durable lessons

1. **A check that cannot fail for the reason you care about is not a check.**
   Verify by rendering/measuring, not by source text. Grep proves a string is
   absent, not that behaviour is correct.
2. **Contrast has two questions, not one:** text-on-badge *and* badge-on-card.
   Checking only the first passes an invisible chip with readable text.
3. **Severity belongs to user impact, not fix difficulty.** Re-read anything
   filed LOW that touches money, dates or permissions.
4. **Query production before trusting a fixture.** Twice the fixture encoded a
   state that does not exist; the correct fix was to the test.
5. **Prove a test non-vacuous by changing ONE side.** Changing the code and the
   expectation together proves nothing.
6. **Test SQL operators on literals, never on live rows.**
7. **Changing an SWR key silently breaks every exact-key `mutate`.** Hit in
   16-6, then again across ten call sites in the deferred-work cluster. Match
   by prefix when a key gains parameters.
8. **A decision made before implementation is cheaper than one discovered
   during it** — most visible in DW-4, where the model choice revealed that a
   daily cron could never recover a deferral.
