## 2. What went well

- **One security spine, reused everywhere.** Dual-path SELECT RLS + membership-gated `SECURITY DEFINER` aggregates (`household_category_totals`, `household_contributions`, `household_goal_breakdown`, `household_category_period_totals`, `household_members_list`) gave a consistent "sums never rows, private excluded" model. 13.8/13.10 became pure composition with **zero new privacy surface**.
- **"Service-role writes + SELECT-only RLS"** kept member-writable RLS paths closed → no cross-household injection class after the 13.5 lesson.
- **Pure-engine reuse** (Epic 12 style) made household AI insights deterministic and fully unit-testable.
- **Transparency held end-to-end** — verified by real-DB RLS tests, not just mocks.

## 3. Challenges & recurring themes

- **The RLS owner-branch (`auth.uid() = user_id`) bit us twice.** 13.5 (writes needed `WITH CHECK` membership or rows could be injected — HIGH) and 13.11 (a removed member still owned/could edit shared categories/goals they created — MED, fixed by reassigning to admin). **Lesson:** whenever a dual-path table is involved, reason about the owner branch on *writes* and on *membership loss*, not just SELECT.
- **AI transaction fixtures broke on every new `transactions` column** (`allowance_id`, then `goal_contribution_id`) — the same 6 fixtures needed editing each time. **Lesson:** a shared transaction fixture factory would kill this recurring tsc failure.
- **PWA push was a multi-session rabbit hole** (out of band): SW never registered (next-pwa register injects via Pages-Router `_app`, absent in App Router), precache 404 on `app-build-manifest.json`, and `NEXT_PUBLIC_VAPID_PUBLIC_KEY` marked **Sensitive** so `vercel pull` omitted it. **Lesson:** App-Router PWA needs explicit SW registration + `buildExcludes` + non-sensitive public keys; add a build-time guard.
- **Manual migrations** caused a "categories won't load" production incident when 020–022 weren't applied. **Lesson:** treat migration application as part of every deploy checklist.
- **Product-decision churn** on goals↔transactions (keep separate → link as a Savings expense) mid-13.9. Handled cleanly, but re-confirm cross-cutting product rules before building.
- **Settings/dashboard tests needed updates** whenever a new household card began fetching (mock the new hook) — minor but recurring.

## 4. Technical debt / known limitations (carry-forward)

- Household insights are **computed on-demand, not persisted** (no cron / history).
- A removed member's `personal_allowances.household_id` is left dangling (private, harmless).
- `getHouseholdGoals` / `getHouseholdInsights` do **N+1 RPC calls** (fine for few goals/categories).
- Insight/coaching **text is English-only** (engine-generated), not i18n'd.
- **Multi-currency** household aggregates are summed without conversion (viewer's formatting only).
- **UX polish gap** (raised by Nikolay) — the household section's controls and mobile/desktop legibility need a pass (see action items 1–3).
