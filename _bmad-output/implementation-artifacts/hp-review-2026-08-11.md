## Decision detail

### D1 — `recommendBudgetLimit` averages the partial current month · HIGH · all 3 layers

`insightRules.ts:158` loops `i = 0..2` from `currentMonth`, so **bucket 0 is the
current, incomplete month**. `forecastEngine.ts:41,79` builds its baseline from
`historicalTransactions` only, holding the current month separately.

So the two features average **different months**. The claim written into
`insightRules.ts:190-193` and `deferred-work.md` — *"at exactly three buckets the
two formulas are identical, so the disagreement cannot occur"* — is false. The
formulas are identical; the inputs are not.

Concretely, a steady 300/month spender:

| Day of month | Buckets | Insight card | Forecast card |
|---|---|---|---|
| 2nd (nothing logged yet) | `[300, 300]` → 2 | **no recommendation at all** | 300 |
| 10th (100 logged) | `[100, 300, 300]` | 233 → recommends **256** | 300 |
| 31st | `[300, 300, 300]` | 300 → recommends 330 ✓ | 300 |

Three separate defects fall out of this:

1. The disagreement HP-2 set out to remove **still exists**.
2. It now **under**-recommends mid-month — the exact failure HP-2's own comment
   says the change avoids.
3. Tightening the guard 2 → 3 **removed a recommendation that used to be
   correct**: at the start of every month the current bucket is empty and is
   skipped, so a steady spender drops to two buckets and gets `null`. A monthly
   blackout that HP-2 introduced.

The guard counts **buckets**, not **complete months** — so it admits the
understated `[5, 300, 300]` and rejects the cleaner two-complete-month case.

**Why the tests missed it.** The `'the two baselines agree'` block asserts
`fixedWindowMonthlyAverage(x) ≈ calculateMean(x)` over the same array — a
property of two pure functions, an arithmetic tautology. It never runs
`recommendBudgetLimit` and `forecastEngine` over one transaction set, which is
the only thing that could have caught this. And `transactionsFor` dates every
month on days 10–12 with `NOW = the 15th`, so the current bucket is always
complete; move `NOW` to the 5th and `does not under-budget a steady spender`
fails.

**Decision:** three materially different fixes —
(a) average the three **complete** months before the current one (matches
`forecastEngine`, makes the claim true, recommendation appears all month);
(b) keep the current month but prorate it to a full-month equivalent;
(c) revert the guard to 2 and fix only the copy.

### D2 — Donut drill-down ignores the selected period · HIGH · all 3 layers

`CategorySpendingChart.tsx:87,151` routes to `/transactions?month=…` using the
route's `month` echo, which is the **anchor month**, never the window
(`route.ts:164`). Select "Year", click a slice worth €10,800, land on July's
€900. The localized `categoryChartAria` — "Select a category to view its
transactions" — makes the same false promise. HP-1 created this by making
`period` drive the donut while leaving the drill-down keyed to `month`.

**Decision:** pass a date range to `/transactions` (does it accept from/to?),
suppress drill-down for non-month periods, or keep month and reword the aria
label.

### D3 — Currency is never converted on this route · MED · blind

`spending-by-category/route.ts` sums raw `amount` with **no** `currency` or
`exchange_rate` handling anywhere (verified: zero matches in the file). Rows in
different currencies are summed unconverted, then rendered with the user's
preferred currency symbol. This is the DW-1 class — which fixed `/api/budgets`,
`/api/wishlist` and `/api/what-if` and **skipped this route**. A month window
mostly hid it; a year window makes a single foreign-currency trip permanently
visible in the donut and every percentage.

**Decision:** port the `getExchangeRates` fallback here, or accept and document.

### D4 — Retro action #1's success criteria were never met, or formally overridden · MED · auditor

Retro §6 #1 required a builder that *"spreads `requireActual` by default and
fails loudly on a missing method"*, success criteria *"no bespoke chain mocks"*.
The shipped helper does the **opposite by design** (a Proxy answering every
property, no `requireActual`), and **33 test files still contain hand-rolled
chains**. The inversion is argued in the file docblock and the PR, but the
retro's criteria were never formally superseded.

**Decision:** accept the redefined criteria and close the item, or keep it open
for the `requireActual` behaviour and the migration.

## Patch (follow-up PRs)

**P1 · HIGH · Wishlist hides cached data on a failed revalidation.**
`WishlistSection.tsx:242` gates on `!!categoriesError` alone. SWR keeps `data`
when a *revalidation* fails, so the options render but the control is disabled
and captioned "couldn't be loaded". `docs/api-conventions.md:920` names this
exact behaviour as wrong — *"hiding cached data because a background
revalidation failed"* — and lists `useWishlist` as the example. My comment cites
that policy while breaking it. Needs `categoriesError && categories.length === 0`,
plus the `logger.warn` the comment claims. Both new tests use
`{data: undefined, error}`, so the `data + error` combination is never exercised.
Related: a `disabled` select leaves the tab order, so the `aria-describedby`
hint is never announced — the a11y test asserts DOM wiring that is true and
unreachable.

**P2 · MED · Chain mock: the permissiveness stops at the chain.** `client` is a
3-key literal — `auth.getSession`, `schema()`, `storage`, `channel` are all
`undefined` → TypeError → route catch → the silent-500 failure the helper exists
to abolish, one level up. `schema('private')` is realistic given the 038 move.

**P3 · MED · Chain mock: unconfigured table returns `data: []`,** which is
**truthy** for a `.single()` guard — `if (!data) return 404` never fires. Track
whether `single`/`maybeSingle` was called and return `null`. Same gap for
`{ count: 'exact' }`: `QueryResult` has no `count`, so routes read `undefined`
and emit `NaN` totals.

**P4 · MED · Chain mock: `expectUserScoped` / `callsTo` default to chain 0.**
Any route querying a table twice (current vs previous window — the norm here)
passes on query 1 while query 2 goes unscoped. That is the documented
3×-recurring "scoping vanishes" bug, reintroduced through a default argument.

**P5 · MED · Chain mock: `calledWith` compares via `JSON.stringify`,** so
`undefined`, `null` and `NaN` are indistinguishable — the confusion most likely
to break a filter. Compare structurally.

**P6 · MED · Chain mock: `jest.clearAllMocks()` desyncs the two assertion
styles** — it clears the memoised `jest.fn`s but not the `calls` array, so
`toHaveBeenCalledWith` sees nothing while `callsTo` returns the previous test's
arguments.

**P7 · MED · 44px enforced on inputs, skipped on the buttons beside them.**
The guard checks `Input`/`Select` only; `<Button size="sm">` (32px) survives on
Save/Cancel/Contribute/Send in every form HP-4 touched — now stacked
full-width, so they are the largest-looking, shortest targets on screen. The
docblock's own premise says "all 8 controls".

**P8 · MED · The HP-4 guard still contains the bug it documents.** `hstackBlocks`
uses `/<HStack[^>]*>/` and the `<Stack` extractor `/<Stack\b[^>]*>/gs` — the
exact `[^>]*` pattern the file spends a paragraph explaining is wrong.
`HouseholdInvites.tsx` already has `mb={pending.length > 0 ? 4 : 0}` on its
`<Stack>`, so the tag truncates **today**; it passes only because `direction`
precedes `mb`. Also: `openingTags(src,'Input')` matches `<InputGroup` /
`<InputLeftElement`; `hstackBlocks` slices a fixed 400 chars; the vacuity guard
covers 1 of 5 files. *(Verified directly.)*

**P9 · MED · No test proves `period` reaches the network.** Delete
`params.set('period', period)` and every test still passes — the component test
mocks the hook, the route test calls `GET` directly, the key test renders with
no args. Assert the built URL.

**P10 · MED · `t(undefined)` crash from an unrecognised server period.**
`data.period` is untyped JSON narrowed only by annotation; an unknown value
indexes `EMPTY_COPY`/`PERIOD_EYEBROW` to `undefined` and throws — taking out the
**whole dashboard page** in the `PERIOD_EYEBROW` case. Narrow with
`isDashboardPeriod`.

**P11 · MED · Trends window label derived from the request, not the response** —
the sibling component in the same commit does this correctly via `data?.period`
and its comment names the very lesson this file ignores. Plus
`useBreakpointValue` is `undefined` on first render, so mobile paints "Last 6
months", fetches 6, then flips to 3 — a visible flip and a second request every
load.

**P12 · MED · `?month=` is unvalidated** → `Invalid Date` → `NaN-NaN-NaN` reaches
the DATE filter → Postgres rejects → 500. `?period=` was given a deliberate
documented fallback for exactly this reasoning; the parameter that *wins over*
it got none.

**P13 · MED · AC 7 unmet — trends month labels are server-generated English.**
`trends/route.ts:126` emits `format(monthDate, 'MMM')` with no locale, rendered
unlocalized on the X axis, the tooltip and the hidden table. Bulgarian users read
"Jan / Feb / Mar". Return `YYYY-MM` and format client-side with `getDateLocale`.

**P14 · LOW · Prefilter window is half a month wider than the analysed window.**
`subMonths(currentMonth, 3)` keeps the day-of-month, so mid-April transactions
satisfy the ≥5 floor while falling into no bucket. The new comment claims the
constant makes fetch, loop and guard agree; it makes the *numbers* agree, not the
*windows*.

**P15 · LOW · `spendingTrendsWindow` has no ICU plural** — `months={1}` renders
"Last 1 months" and grammatically wrong Bulgarian. Every other count-bearing key
in these files uses `plural`.

**P16 · LOW · Fake-timer reset lives inside a test body,** so a failed assertion
leaves every later test in the file on the wrong system date.

**P17 · LOW · `where-its-going.test.tsx` claims coverage it lacks** — the
docblock says it pins "nothing in these three components renders a hardcoded
English literal", but only `CategorySpendingChart` is rendered; the other two are
reached by a `t('…')` regex that proves keys exist, not that literals are gone.
Its dynamic-key blind spot is real too: `t(EMPTY_COPY[…])` and
`t(PERIOD_EYEBROW[…])` are invisible to it, and `dashboard/page.tsx` is not in
the list at all.

**P18 · LOW · `docs/api-conventions.md:428` still documents `month` as the only
parameter** for this route and omits `period` from the response body.

**P19 · LOW · `BalanceFlowHero` half-controlled props.** `period` and
`onPeriodChange` are independently optional, so passing only `period` compiles
and yields a selector whose clicks write to dead internal state.

**P20 · LOW · `fetchedDirectlyBy` is an unverified escape hatch** in the suite
that claims routes are the source of truth — free text, checked by nothing, and
the cheapest way to silence the guard is to add one.

## Defer

- **SWR keys freeze `today=` at render time** and go stale across midnight —
  real, but it affects all five dated hooks from the deferred-work batch, not
  just this one. Needs a shared fix (re-key on focus/visibility).
- **Persisted cache keys grow without eviction**; HP-1 multiplied the keyspace
  by four by adding the period dimension. The provider's LRU is still a TODO and
  it stops persisting silently at 50MB.
- **The ±1-day `today` clamp is amplified** into ±1 week/month/year at period
  boundaries. The tolerance was sized when the value only ever picked a month.

## Dismissed (3)

- *Exact-key `mutate` callers break* — verified: no exact-key `mutate` targets
  this endpoint; all callers use prefix matching or the full URL.
- *Other `CategorySpendingChart` mount sites lose their heading* — verified:
  one mount site only.
- *Scope drift (`!src/test-utils/**` coverage exclusion, `Text as="h3")* —
  defensible; the heading promotion is an a11y improvement.
