## 2. What went well

- **The adversarial triple-review paid for itself repeatedly.** The clearest ROI: 15-7's **live production regression** — the dormant `user_feature_state` counters were made authoritative without a backfill, which hid the heatmap/projections/subscriptions from every established user (the main account: 136 transactions, counter reading 0). Only the Edge Case Hunter caught it; the other two reviewers missed it. Fixed same session (migration 040 backfill + atomic RPC).
- **Standing engineering rules crystallized and compounded.** Each story's review produced a rule the next story applied: never-throwing gates must *return* an outcome (15-5); fire-and-forget promises drop on Vercel — *await* best-effort work (15-5); one-shot events never ride cacheable payloads (15-3/15-4); server-derived lifecycle tables get service-role writes + SELECT-only RLS (15-4, now a rule); a client gate's **fail direction is a deliberate choice by which harm is worse** — 15-6 fails closed (don't flash opted-out UI), 15-7 fails open (don't hide an earned feature); aria-live belongs on a persistent hidden node, never a whole conditionally-mounted card (15-8).
- **Checkbox honesty became a first-class review target.** 15-5 exposed 3 task checkboxes marked done without the promised tests (stale tx-route mocks silently degrading). Every subsequent story (15-6, 15-7, 15-8) came back *clean* on that axis — the "a checked box requires the test to exist and assert its claim" discipline held.
- **Prod migrations stayed disciplined.** All 7 migrations applied via MCP with post-apply verification each time; the 038 security pass cleared the advisor backlog; re-run-safety was built in (guards, `ON CONFLICT`, `IF NOT EXISTS`) after the manual-rerun habit was noted.
- **Pure-engine architecture continued to serve.** streakEngine, budgetScoreEngine, achievementEngine, comebackEngine, disclosureEngine — all pure, deterministic, trivially unit-testable; the DB/IO stayed in thin services. This is why the test count could grow +313 cheaply.

## 3. What was hard / what didn't go well

- **The 15-7 regression was a design blind spot, not a coding error.** The "non-regressive gating" design *assumed* the counter reflected real usage; it had been dormant zeros since Epic 11. **Lesson: before making any dormant/latent table authoritative, audit its ACTUAL production state — don't assume the schema's intent equals its data.**
- **Subagent reviewers died on usage-credit exhaustion mid-run** (15-6 and part of 15-7). Recovered by completing the reviewers' intended checks inline and switching the session model to Opus — but two reviews were partly single-threaded rather than truly parallel/adversarial.
- **Clock-rotted test fixtures surfaced.** 15-6 work tripped over 15-4 fixtures that hardcoded `expires_at: 2026-07-20` — they went red the day the calendar passed them. Fixed to clock-relative; the lesson (any fixture compared against `Date.now()` must be clock-relative) is now recorded but had to be learned twice.
- **A backtick in a `git commit -m "…"` string triggered bash command-substitution** and silently dropped a word from a commit body. Switched to heredocs for messages containing backticks.
- **Two platform constraints had to be *accepted* rather than fixed:** Chakra v2 toasts have no `prefers-reduced-motion` branch (15-3/15-8, documented as graceful degradation), and the JSONB preferences read-modify-write race (pre-existing 8.3) was re-confirmed but deferred as it now has more adjacent toggles.

## 5. Key lessons (durable)

1. **Audit a table's real data before making it authoritative.** A dormant/latent column's *intent* is not its *state*. Backfill first.
2. **A never-throwing gate must return its outcome**, or every caller's telemetry lies.
3. **Await best-effort work on Vercel** — fire-and-forget is dropped when the function freezes after the response.
4. **Fail-open vs fail-closed is a design decision keyed to which error is worse** — hiding an earned feature vs. flashing an opted-out one.
5. **aria-live goes on a persistent hidden node**, never on a whole conditionally-mounted card (mounts-with-content = no announce + over-announce).
6. **A checked task box requires the test to exist and assert the claim** — the review will find stale/absent mocks that silently degrade.
